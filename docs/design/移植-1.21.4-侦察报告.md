## 1. 项目本质

BlackBoxPro（BBP）是 Minecraft **自动化黑盒测试框架**（Kotlin）。

- 服务端插件（Paper，`plugin/` 模块）通过 Plugin Message Channel 下发 JSON 指令
- 客户端 Mod 在客户端**模拟真实玩家行为**（移动、方块交互、GUI 操作、截图、查询）并回传结果
- 另有 HTTP API（Mod:38081 / Plugin:38080）供外部工具直连

### 模块布局

```
BlackBoxPro/
├── common/                      # 无 MC 依赖的共享协议层（Gson, JVM 1.8 目标）
├── mod/                         # 独立 Gradle 工程（settings.gradle.kts 聚合）
│   ├── 1.21.11/{runtime,fabric,neoforge}
│   ├── 1.21.1/{runtime,fabric,neoforge}
│   └── 1.12.2/{runtime,forge}   # 独立 Gradle 根，JDK 8
├── plugin/                      # 独立 Gradle 根（TabooLib 6.2.4）
└── build.gradle.kts             # 根聚合：buildAll / collectJars
```

### 关键分层契约（**移植的核心**）

`mod/{ver}/runtime` 目录里有**两类完全不同的东西**：

| 子路径 | 性质 | 是否依赖 MC |
|---|---|---|
| `runtime/src/main/kotlin/com/blackboxpro/runtime/` | 纯 Kotlin 共享桥接层 | **否**（只依赖 common + slf4j + gson） |
| `runtime/src/main/kotlin/com/blackboxpro/neoforge/` | NeoForge/Mojang 命名下的 MC 实现 | 是 |

`mod/{ver}/fabric/build.gradle.kts` 通过这行把**共享桥接层源码直接编入 fabric 模块**：

```kotlin
val runtimeSharedDir = project(":{ver}:runtime").file("src/main/kotlin/com/blackboxpro/runtime")
the<SourceSetContainer>()["main"].java.srcDir(runtimeSharedDir)
```

**含义**：Fabric 端不需要 runtime 产出的 jar，只需要那 9 个共享桥接源文件存在于 runtime 目录下。
**这正是绕开 NeoForm 的关键**：若 runtime 模块的 `neoforge` 子包被移除，runtime 就是一个纯 Kotlin 库，不需要 `maven.neoforged.net`。

`runtime` 共享桥接层文件清单（1.21.11 有 10 个，1.21.1 有 9 个）：

```
com/blackboxpro/runtime/action/AsyncClientActionSupport.kt
com/blackboxpro/runtime/bindings/FabricBindings.kt
com/blackboxpro/runtime/bindings/NeoForgeBindings.kt
com/blackboxpro/runtime/bindings/ScreenRenderBridge.kt      # 仅 1.21.11 有
com/blackboxpro/runtime/bindings/SharedSlf4jLoggerSupplier.kt
com/blackboxpro/runtime/dispatcher/RuntimeCommandDispatcherBootstrap.kt
com/blackboxpro/runtime/util/pathfinding/PathNode.kt
com/blackboxpro/runtime/util/RuntimeBlockFaceUtil.kt
com/blackboxpro/runtime/util/RuntimeJsonUtil.kt
com/blackboxpro/runtime/util/RuntimeMathUtil.kt
```

已验证：这些文件**零 `net.minecraft.*` 导入、零 `org.tabooproject` 导入**。

## 3. 基线选择：决定性证据

**结论：以 1.21.11 为语义基线，但对每个文件用 1.21.4 的 Yarn 映射逐项校正。1.21.1 作为次要参考。**

理由（基于 Yarn mappings 的量化证据，非推测）：

### 证据 A — `Input` 类（移动系统核心，决定 InjectedInput 架构）

| 版本 | 字段/方法 |
|---|---|
| 1.21.1 | `tick(ZF)V`（带参）、`pressingForward` 等**独立 boolean 字段** |
| **1.21.4** | **`tick()V`（无参）、`playerInput` 字段、`movementSideways`/`movementForward`** |
| 1.21.11 | `tick()V`（无参）、`playerInput` 字段、`movementVector` |

→ 1.21.4 与 1.21.11 **同代**（输入系统重构后），与 1.21.1 **不同代**。
→ 这直接决定 `InjectedInput.kt`、`PlayerMoveAction`、`PlayerMoveLookAction`、`PlayerInputAction` 的写法。

### 证据 B — `PlayerInput` 类存在性

- 1.21.1：**不存在**
- 1.21.4：**存在**（`class_10185`，与 1.21.11 同一 intermediary）
- 1.21.11：存在

### 证据 C — 成员相似度评分（115 个 `net.minecraft.*` 导入，Jaccard 比对）

| | closer-to-1.21.11 | closer-to-1.21.1 | tie |
|---|---|---|---|
| 1.21.11 源码 vs 1.21.4 | 14 | 22 | 67 |
| 1.21.1 源码 vs 1.21.4 | 14 | 25 | 65 |

→ 单纯成员相似度上**两者接近**（1.21.4 是真正的中间版本）。

### 证据 D — 1.21.11 代码中**仅 4 个**导入在 1.21.4 不存在

```
net.minecraft.network.packet.c2s.play.DebugSubscriptionRequestC2SPacket   # world.debug 包整体不存在
net.minecraft.world.debug.DebugSubscriptionType                            # 同上
net.minecraft.world.debug.DebugSubscriptionTypes                           # 同上
net.minecraft.screen.sync.ItemStackHash                                    # screen.sync 包整个不存在
```
（另有 1 个 `net.minecraft.client.gui.screen.ingame.` 为通配符导入，非真实缺失）

1.21.1 代码在 1.21.4 上**仅 1 个**缺失导入：`PickFromInventoryC2SPacket`（1.21.4 已拆分为 `PickItemFromBlockC2SPacket` + `PickItemFromEntityC2SPacket`）。

### 证据 E — `ClickSlotC2SPacket` 构造函数

| 版本 | 构造签名 |
|---|---|
| 1.21.1 | `(slot:I, revision:I, actionType, button:I, syncId:I, modifiedStacks, stack)` |
| **1.21.4** | **与 1.21.1 完全相同** |
| 1.21.11 | `(syncId:I, revision:I, slot:S, button:B, actionType, modifiedStacks, cursor:ItemStackHash)` |

→ 网络层（1.21.2 前的包结构）1.21.4 仍承袭 1.21.1。

### 综合判断

**1.21.4 是货真价实的"中间版本"**：
- **输入/渲染/UI 层** → 已演进到 1.21.11 形态（Input 重构、PlayerInput、BlockHitResult、PlayerMoveC2SPacket、CreateWorldScreen、TitleScreen…）
- **网络包层** → 仍是 1.21.1 形态（ClickSlotC2SPacket、PlayerInteractEntityC2SPacket、CustomPayloadC2SPacket…）

**因此不能整目录复制任一侧**。正确做法是**以 1.21.11 目录为模板复制**（因为文件数更多、含 accesswidener + mixin + LeftClickAction + QueryTooltipStateAction，功能更全），然后**逐文件用 1.21.4 Yarn 映射校正**。

## 5. 移植实施计划

### 阶段 1：骨架（无 MC 依赖，可独立验证）
1. `cp -r mod/1.21.11 mod/1.21.4`
2. 改写 `mod/1.21.4/gradle.properties`（版本号）
3. `mod/1.21.4/runtime/build.gradle.kts`：**移除 `net.neoforged.moddev` 插件与 `neoForge {}` 块**，改为纯 `java-library + kotlin.jvm`（因 NeoForge maven 不可达，且 Fabric 路径不需要 Neoforge 实现）
4. 删除 `mod/1.21.4/runtime/src/main/kotlin/com/blackboxpro/neoforge/`（该部分仅 NeoForge 用）
5. 删除 `mod/1.21.4/neoforge/`（本次仅 Fabric）
6. `mod/settings.gradle.kts`：注册 `1.21.4:runtime` 与 `1.21.4:fabric`
7. `mod/build.gradle.kts`：加入 1.21.4 构建与 collectJars

### 阶段 2：Fabric 平台源码适配（**主体工作量，多 agent 并行**）
对 `mod/1.21.4/fabric/src/main/kotlin/com/blackboxpro/fabric/**` 逐个文件，以 1.21.4 Yarn 映射为准校正 API。

**已知必改点（预侦察结论）**：
- `util/InjectedInput.kt` — Input 重构：`tick()` 无参 + `playerInput` + `movementSideways/Forward`（**不是** 1.21.11 的 `movementVector`）
- `action/container/ClickSlotAction.kt` — `ClickSlotC2SPacket` 用 1.21.1 形态签名（`getStack()`、Int 型 slot/button）
- `action/container/PickItemFromBlockAction.kt` / `PickItemFromEntityAction.kt` — 1.21.4 已有拆分包（`class_10370`/`class_10371`）
- `action/client/ScreenshotTooltipAction.kt` — 1.21.4 **无** `screen.sync.ItemStackHash`、**无** `world.debug.*`
- `action/debug/DebugSampleAction.kt` — 1.21.4 无 1.21.11 的 `world.debug.*` 新体系，**但仍有 1.21.1 形态的等价能力**（`DebugSampleSubscriptionC2SPacket(DebugSampleType)`），故采用 1.21.1 形态的完整实现（详见修复指引 §5）
- `action/query/QueryTooltipStateAction.kt`、`util/ContainerTooltipHelper.kt` — tooltip API 需按 1.21.4 校正
- `action/advanced/*`（BookUpdate/RecipeBook/CraftRequest）— 部分类更接近 1.21.11
- 反射调用点（5 个文件用 `org.tabooproject.reflex`）— 反射目标名需按 1.21.4 校正
- `GameRendererMixin.java` — 注入目标 `GuiRenderer;incrementFrame()V` 需在 1.21.4 中核实
- `blackboxpro.accesswidener` — `HandledScreen x/y` 字段在 1.21.4 已确认存在（`f x desc=I`）

### 阶段 3：构建验证
`./gradlew :1.21.4:fabric:classes` 迭代至零编译错误。这是**客观验收线**。

### 阶段 4（可选，需用户参与）
按上游 skill 要求，运行时验收需**用户手动启动** Paper 1.21.4 服务端与 Fabric 客户端（AI 不得代启动长驻进程），然后跑 `/blackbox exec` 全量测试并比对通过率。

## 6. 给子 agent 的工作规约

每个 agent 处理一组文件时请遵守：

1. **权威依据是 `yarnq.js` 查出的 1.21.4 映射**，不是 1.21.1/1.21.11 的代码形态，也不是记忆中的 MC API。
2. 修改前先查目标类在 1.21.4 的实际成员；不确定就查，禁止猜测方法名。
3. 保持与相邻代码一致的风格（Kotlin 惯用语、中文注释、`?:`/`?.let` 而非 `!!`）。
4. **不要把 1.21.11 的特性硬塞进 1.21.4**（如 `ItemStackHash`、`world.debug.*` 在 1.21.4 不存在）；也不要退回 1.21.1 的旧形态（如 Input 的带参 `tick`）。
5. 若某 Action 依赖的 1.21.4 API 确实不存在，**报告并标注**，不要臆造。
6. 不要修改 `common/`（协议层与 MC 版本无关）。
