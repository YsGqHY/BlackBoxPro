### 3. `util/ScreenshotHelper` — 退回 1.21.1 形态 ✅已确认

1.21.4 的 `ScreenshotRecorder.takeScreenshot` **返回 `NativeImage`**（同步），而 1.21.11 改成了回调式（`takeScreenshot(framebuffer) { image -> ... }` 返回 `ScreenshotRecorder`）。

```
1.21.4:  m takeScreenshot(framebuffer)  desc=(Lnet/minecraft/class_276;)Lnet/minecraft/class_1011;   // → NativeImage
1.21.4:  NativeImage: m getWidth() m getHeight() m writeTo(path)
```

**做法**：**采用 `mod/1.21.1/fabric/.../util/ScreenshotHelper.kt` 的写法**：

```kotlin
fun captureAsync(directory: Path, fileName: String, callback: (Result<ScreenshotResult>) -> Unit) {
    val framebuffer = MinecraftClient.getInstance().framebuffer
    try {
        val image = ScreenshotRecorder.takeScreenshot(framebuffer)
        Files.createDirectories(directory)
        val filePath = directory.resolve("$fileName.png")
        image.writeTo(filePath)
        val fileSize = Files.size(filePath)
        val w = image.width
        val h = image.height
        callback(Result.success(ScreenshotResult(filePath, w, h, fileSize)))
    } catch (e: Exception) { callback(Result.failure(e)) }
}
```

⚠️ **注意回调类型**：1.21.11 版把 callback 改成了 `Consumer<...>`（用 `callback.accept`）。1.21.1 版用 Kotlin 函数类型 `(Result<T>) -> Unit`。改动 `ScreenshotHelper` 的签名会**影响所有调用方**——请先 `grep -rn "ScreenshotHelper.captureAsync" mod/1.21.4/` 找出调用点并保持一致。推荐直接沿用 1.21.11 的 `Consumer` 签名（只改内部实现），这样调用方不用动。

### 4. `util/InjectedInput` — 采用 1.21.4 独有形态 ✅已确认

1.21.4 的 `Input` 类：

```
class net/minecraft/client/input/Input  (= net/minecraft/class_744)
  -- fields --
  f playerInput       desc=Lnet/minecraft/class_10185;    // PlayerInput
  f movementSideways  desc=F
  f movementForward   desc=F
  -- methods --
  m tick()  desc=()V            // 无参！
  m jump()  desc=()V
  m getMovementInput()  desc=()Lnet/minecraft/class_241;
```

对比：
- 1.21.1：`tick(ZF)V`、字段 `pressingForward` 等
- 1.21.11：`tick()V`、字段 `playerInput` + `movementVector`（`Vec2f`）
- **1.21.4：`tick()V`、字段 `playerInput` + `movementSideways`/`movementForward`（两个 float）**

`PlayerInput` 在 1.21.4 存在（`net/minecraft/util/PlayerInput`，与 1.21.11 同一 intermediary `class_10185`）。

**做法**：**1.21.11 的写法只需一处改动**——把 1.21.11 里的

```kotlin
movementVector = Vec2f(sidewaysValue, forwardValue).normalize()
```

换成 **1.21.4 的两个独立字段**：

```kotlin
movementSideways = sidewaysValue
movementForward = forwardValue
```

（`playerInput = PlayerInput(...)` 那行保持不变。）

⚠️ 请用 `node yarnq.js yarn/yarn-1.21.4+build.8 class net/minecraft/util/PlayerInput` 确认 `PlayerInput` 构造器参数顺序后再定稿（1.21.11 是 `(forward, backward, left, right, jump, sneak, sprint)`）。同时确认 1.21.4 的 `Input.getMovementMultiplier` 是否可用（1.21.4 的 `KeyboardInput` 有该方法）。

### 5. `action/debug/DebugSampleAction` — 采用 1.21.1 形态的完整实现 ✅（原判断已修正）

> **⚠️ 本节最初判断有误，已修正。** 最初认为"1.21.4 没有 debug 订阅系统"，据此建议降级为 stub。
> 后续用 `javap` 对构建实际使用的 remapped 1.21.4 jar 做字节码核验，证明该判断**不成立**：
>
> 1.21.4 **完整具备** 1.21.1 形态的调试采样订阅能力：
> ```
> net.minecraft.network.packet.c2s.play.DebugSampleSubscriptionC2SPacket
>     public DebugSampleSubscriptionC2SPacket(net.minecraft.util.profiler.log.DebugSampleType);
> net.minecraft.util.profiler.log.DebugSampleType
>     public static final DebugSampleType TICK_TIME;
> net.minecraft.network.listener.ServerPlayPacketListener#onDebugSampleSubscription
> ```
> 且 1.21.4 与 1.21.1 的 `class_9179` tiny 映射段逐字节相同。
>
> **真相**：1.21.4 **不存在**的是 1.21.11 引入的 `world.debug.*` 重构体系
> （`DebugSubscriptionRequestC2SPacket` / `DebugSubscriptionTypes`）——那是同一能力在
> 更高版本的重构，不代表 1.21.4 缺少该功能。

**最终做法**：恢复为**功能完整的实现**，与 `mod/1.21.1/fabric/.../action/debug/DebugSampleAction.kt` 逻辑一致：

```kotlin
handler.sendPacket(DebugSampleSubscriptionC2SPacket(DebugSampleType.TICK_TIME))
return ActionResult.ok("Subscribed to debug sample: tick_time")
```

**教训**：判断"某功能在目标版本不存在"时，**必须用 javap 查字节码**，不能只看 Yarn 映射里有没有 1.21.11 的那些类名——API 重构会让新名字消失，而功能本身往往仍在旧名字下。

## 工作纪律

1. **改完必须编译验证**。不要一次改 10 个文件再编译——分批，每批编译一次。
2. **一次只有一个 Gradle 构建**。若发现 "Gradle build daemon disappeared"，先 `ps aux | grep java` 杀掉残留进程再重试。
3. **不要修改 `common/`**（协议层与 MC 版本无关，且被其它版本共用）。
4. **不要修改 `mod/1.21.1/`、`mod/1.21.11/`、`mod/1.12.2/`**（它们是参照物，改动会污染基线）。
5. 只改 `mod/1.21.4/` 下的文件。
6. Kotlin 风格：禁 `!!`，用 `?.let` / `?:`；沿用文件内既有的中文注释风格。
